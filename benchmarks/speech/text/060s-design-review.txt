The purpose of tomorrow's design review is to decide how the import screen should handle interrupted work. We are not choosing colours or rewriting the entire interface. A user should be able to close the window, return later, and understand which files finished and which still need attention. The screen should show a useful summary before offering detailed logs. If a file fails, the retry action must not create a second copy of a file that already succeeded. Please bring examples covering a normal import, a lost connection, and a restart halfway through the queue. We should also consider people using a keyboard or a screen reader. Once we agree on those behaviours, we can divide the implementation into a small set of changes and give each one a concrete acceptance check. I will write down the decisions during the meeting and circulate the notes afterwards, including any questions that remain open.
